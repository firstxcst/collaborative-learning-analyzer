# 计分模型说明

本文件说明协作健康分是怎么算出来的，以及**它目前能证明什么、不能证明什么**。

## 一、旧模型为什么是坏的

旧实现（v1.0.0）：

```
均衡度     = 1 - 2 × std(个体贡献度)
协作模式   = 0.4×均衡度 + 0.3×观点碰撞 + 0.3×论证深度
协作健康分 = (0.3×均衡度 + 0.4×协作模式 + 0.3×主题相关) × 100
个体贡献度 = 0.3×发言 + 0.3×全局语义相关度 + 0.2×非语言 + 0.1×指点 + 0.1×全局凝聚度
```

三个致命问题（都经实测确认）：

1. **`std` 度量的是离散程度，不是水平高低。**
   全体成员得分都趋近 0 时 `std → 0`，于是 `均衡度 → 1`。实测：全员一言不发的小组
   得 **90.5 分（excellent）**，比正常均衡小组的 87.9 分**更高**。
2. **常数项稀释标准差。** 每个成员的贡献度里都叠加了同一批全局常数
   （`0.3×全局语义相关度 + 0.1×全局凝聚度`），使 `std` 被系统性压低，均衡度恒偏向 1。
3. **量表区间不可达。** 贡献度上限只有 0.3（发言权重 0.3，其余四项中两项恒为 0、
   两项为常数），因此 `std ≤ 0.15`、`均衡度 ≥ 0.7`，健康分的**结构性下界约为 32.2 分**。
   文档承诺的 `critical`（0–29，"立即协作严重不足"）**在数学上不可能出现**。

## 二、新模型（v1.1.0）

```
activity  = min(1, 组内发言总时长 / (总时长 × target_talk_ratio))
evenness  = (1/HHI - 1) / (n - 1)          , HHI = Σ pᵢ²,  pᵢ = tᵢ / Σt
depth     = 加权平均(观点碰撞速率得分, 论证深度, 共识质量)   # 缺失子项重新归一化
quality   = 加权平均(evenness, topic_relevance, depth)        # 缺失维度重新归一化
health    = 100 × activity × quality
```

设计要点：

| 设计 | 解决的问题 |
|------|-----------|
| 均衡度改用 **HHI（Herfindahl–Hirschman 指数）的归一化反向值** | 只对**份额分布**敏感，与整体水平无关，且份额全为零时返回 `0` 而不是满分 |
| 活跃度作为**乘法门控** | 沉默必然归零，`critical` 重新可达；全区间 0–100 都可达 |
| 缺失模态**不填默认值**，改为在可用维度上**重新归一化权重** | 杜绝“解析失败静默变成 0.5 分”这类编造 |
| 个体语义分**逐人**取得 | 不再把全局分数复制给每个成员 |
| 权重集中到 `FusionEngineConfig` 并在 `validate()` 中校验和为 1 | 权重写错会立刻报错，而不是静默改变模型 |

`evenness` 的解析性质（有单元测试逐条断言）：

| 份额 | evenness |
|------|----------|
| 完全均等 `[1,1,1,1]` | 1.0 |
| 两人对半 `[1,1,0,0]` | 1/3 |
| 一人独占 `[1,0,0,0]` | 0.0 |
| 全员沉默 `[0,0,0,0]` | **0.0**（旧模型在这里返回 1.0） |

## 三、必须说清楚的话：权重**尚未经过实证标定**

新模型的权重（`quality_weights`、`depth_weights`、`contribution_weights`、
`target_talk_ratio = 0.45`、各归一化参考值）是**工程默认值**，
依据是“量纲合理、单调性正确、边界行为正确”，**不是**从真实课堂数据标定出来的。

这一点和旧模型的差别在于：

- 旧模型的问题是**逻辑错误**（度量反向、区间不可达、静默编造），这与权重取值无关，
  改权重也修不好；
- 新模型逻辑正确，但**权重取值仍待标定**。要让它成为研究工具，还需要：
  1. 采集真实课堂小组讨论数据；
  2. 由两名以上编码者按成熟框架（如 ICAP、On/Off-task 编码）独立人工编码；
  3. 以人工编码为基准，考察人机一致性（Cohen's Kappa / ICC）与分数区分度；
  4. 据此调整权重与阈值，并报告信效度证据。

**在完成上述步骤之前，本工具的输出只能作为教学参考线索，不得作为评价学生的依据，
也不得在论文中作为测量结果使用。**

## 四、可复现性

- 阈值与权重全部集中在 `src/config.py` 的 `FusionEngineConfig`，可通过代码或环境变量调整；
- 回归测试（`tests/test_scoring.py`）对单调性、边界、五级可达性、缺失模态处理逐条断言；
- `tools/make_fixtures.py` 生成的真实媒体夹具可用于端到端回归，
  但它**不能**替代真实课堂数据用于效度检验（见 `fixtures/README.md`）。
